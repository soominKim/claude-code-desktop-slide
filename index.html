단계별 역할 · STEP 1

STEP 1 · PRD 한 장 → 돌아가는 화면

외부 API와 Supabase는 아직 연결하지 않습니다. 샘플 데이터만으로 화면과 흐름을 먼저 완성합니다.
반드시 "Next.js 기반의 웹앱으로 만들어줘"라고 지시합니다. 단순 웹페이지가 아니라 로그인 · API · 데이터베이스를 나중에 붙이고 Vercel로 바로 배포할 수 있는 구조가 됩니다. (왜 그런지는 다음 장)
왜 샘플 데이터로 먼저?화면이 틀렸는지, 데이터가 틀렸는지, 연결이 틀렸는지를 한 번에 겪으면 원인을 못 찾습니다. 문제를 한 겹씩 분리합니다.
룩앤필 이미지를 함께 첨부합니다.PRD의 "첨부하는 이미지 디자인을 적용한다"가 그때 동작합니다. 말보다 그림이 빠릅니다.
내 서비스는 PRD만 바꿉니다.첫 줄 "이 PRD대로 Next.js 기반의 웹앱으로 만들어줘."는 그대로. "지금은 연결하지 말고 샘플로만" 문장도 꼭 남깁니다.

단계별 역할 · STEP 1

왜 Next.js 기반으로 지시하나

예전에는 화면(FE)과 서버(BE)가 서로 다른 섬이었습니다. Next.js는 두 섬을 한 폴더에 담습니다. Node.js는 그 Next.js가 돌아가는 바탕이라 설치만 해 두면 됩니다.
화면과 /api 서버 코드가 같은 프로젝트 안에서 바로 연결되니, 로그인 · API · DB를 나중에 붙이기 쉽고 Vercel 배포도 그대로 이어집니다.
단계별 역할 · STEP 2

STEP 2 · API 연결하기

직접 만들지 않는 데이터를 밖에서 가져옵니다. 오늘 예제는 PokéAPI와 WeatherAPI.com.
API
연결 통로
내 서비스가 다른 서비스의 데이터나 기능을 가져다 쓰는 길. 날씨 · 지도 · 주가를 직접 만들지 않고 요청해서 받습니다.
KEY
출입증
누가 쓰는지 확인하는 표. 제공자는 Key로 사용량을 제한하고 과금합니다. 발급은 사람이 합니다.
.env
Key 보관함
Key는 코드에 적지 않고 .env 파일에. .gitignore로 GitHub에 올라가지 않게 막습니다. 설정은 Claude가, 값 붙여넣기는 사람이.
Key가 필요 없는 API(PokéAPI)도 있고, 필요한 API(WeatherAPI)도 있습니다. "어디에 Key를 넣으면 되는지 알려줘"가 핵심 요청입니다.
두 카드 모두 "실시간 연결됨" : API가 붙은 뒤의 모습
